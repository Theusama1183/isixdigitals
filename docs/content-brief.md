# Content brief — iSixDigitals (US + UK)

This file is written to be handed to a writer (Claude) as-is. It contains the
target pages, the exact keywords, the live SERP competition, and the constraints
the copy must respect.

---

## 0. Ground rules — read before writing anything

**Market.** The site targets **US and UK English search only**. Pakistan was
checked and every target term has ~0 monthly volume there. Write for a reader in
London, Manchester, New York, Chicago or Los Angeles. Do not mention Lahore,
Pakistan, local currency (PKR), or "clients worldwide" as a selling point.

**Business.** iSixDigitals is a one-person studio-website design practice run by
**Usama Adeel**, working with studios since **2021**. Services: studio website
design, website redesign, inquiry & booking journeys, search & measurement.

**Hard constraints — do not break these:**

1. **No invented results.** No "increased bookings by 40%", no "300+ studios
   served", no star ratings, no revenue claims. There is no verified data behind
   any number, so no number goes in.
2. **No invented testimonials or case studies.** Do not write quotes from
   clients. Do not describe projects as if iSixDigitals delivered them.
3. **No client names.** Third-party studios may be referenced only in the
   examples articles, only as publicly available reference material ("a public
   example of X"), never as clients.
4. **No placeholder text.** No `[Studio Name]`, no lorem ipsum, no "insert
   here". Every sentence must be publishable.
5. **No fake urgency or guarantees.** No "limited spots", no "guaranteed page 1",
   no "rank #1 on Google".
6. **Prices.** Do not state prices. Say how scope is decided instead.
7. **Contact details.** Do not hardcode an email or phone. The site injects
   them from environment variables. Write "get in touch" / "send a project
   brief", or link to `/contact`.

**Voice.** Direct, specific, calm. Short declarative sentences. British spelling
is acceptable and currently used on the site (`organise`, `colour`,
`specialise`) — stay consistent with that. No hype adjectives ("stunning",
"game-changing", "cutting-edge"). No em-dash-heavy AI rhythm. No rhetorical
"Not only X, but Y" constructions. Write like a person who has actually built
websites for studios and is telling you what matters.

**The gap to fill.** Nobody explains what a dance studio website actually has to
do. Write the page that answers that.

**Required structure**

- **H1** — must contain "dance studio website design" or "websites for dance
  studios" naturally. Max ~65 characters. No colon-stuffed SEO H1.
- **Intro (60–90 words)** — who this is for, what changes when the site is right,
  what the page covers. No throat-clearing.
- **H2: What a dance studio website has to do** — four to five concrete jobs:
  help a new student find the right class and level; make the timetable legible
  on a phone; explain what a trial class involves; separate adult classes from
  children's classes from vocational training; give parents and adult students
  different paths.
- **H2: The pages a dance studio actually needs** — home, timetable/classes,
  class detail, about/teachers, pricing or fees, trial booking, contact. For each,
  one sentence on what it must contain. Avoid a generic "Home, About, Services,
  Contact" list.
- **H2: Timetables, levels and the mobile problem** — the specific UX failure:
  a PDF timetable, a grid that breaks on a phone, levels with no explanation.
  Explain what to do instead.
- **H2: Trial classes and enquiries** — the difference between a trial booking, a
  term registration and a general question, and why one form cannot serve all
  three.
- **H2: What working together looks like** — honest, no fake metrics. Reference
  the existing `/process` page and summarise the four stages in two sentences
  each.
- **H2: Questions dance studios ask** — 5–6 FAQ items with real answers. Suggested
  questions: Do we need to move off our current platform? Can you work with our
  existing timetable software? How long does a studio website take? What do you
  need from us? Can we update the timetable ourselves?
- **Closing CTA** — link to `/contact`, no fabricated proof.

**Must include these facts** (from the existing site, keep consistent):
- Class styles, levels and schedules must be easy to compare.
- A first or trial class must be explained clearly.
- Class pages connect to the right registration or booking tool.
- Typical pages: home, timetable/classes, class detail, about, contact.

**Do not include:** dance-studio marketing advice (that is a different business),
enrolment statistics, "we increased enrolment by X".

## 5. Metadata for every page

Deliver these alongside the body copy.

- **Title tag:** 50–60 characters. Format `Primary phrase | iSixDigitals`. The
  site appends the brand suffix itself if you give it a bare title; if you write
  the full title, say so explicitly.
- **Meta description:** 140–155 characters. Concrete, no keyword stuffing, no
  exclamation marks, no "learn more".
- **H1:** one per page, distinct from the title tag where possible.
- **Canonical path:** the URL listed above.
- **Schema type:** `Service` for the three service pages, `Article` for editorial.
  Do not write FAQPage schema; that rich result is no longer reliable.

## 7. What to hand back

For each page, in this order:

1. URL and page type
2. Title tag, with character count
3. Meta description, with character count
4. H1
5. Full body copy in Markdown, with H2/H3 structure exactly as briefed
6. FAQ block as `Question` / `Answer` pairs
7. Internal links used, with anchor text and target URL
8. Word count

If a section cannot be written without inventing a fact, a result, a client or a
testimonial, leave it out and say so. An honest page with 900 words beats a
complete-looking page with three fabricated claims on it.
